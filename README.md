# scandroid
# Media Collector

PowerShell-скрипт для сбора фотографий и видео из нескольких каталогов в единый медиаархив с автоматической сортировкой по дате съёмки, поиском дубликатов фотографий и возможностью безопасного тестового запуска.

Скрипт предназначен для упорядочивания больших личных фото- и видеоархивов, распределённых по разным дискам и каталогам.

## Возможности

* **Сбор медиа из нескольких каталогов.** Можно указать любое количество исходных директорий на разных дисках.
* **Автоматическая сортировка по дате.** Файлы раскладываются по годам и месяцам.
* **Извлечение метаданных.** Для определения даты используется ExifTool.
* **Поиск дубликатов фотографий.** Сравнение содержимого по SHA-256 позволяет обнаруживать одинаковые фотографии независимо от имени файла.
* **Сохранение оригиналов.** Исходные файлы копируются, а не перемещаются и не изменяются.
* **Защита от перезаписи.** Если файл с таким именем уже существует, подбирается уникальное имя.
* **Возобновление после прерывания.** Журнал позволяет пропускать файлы, успешно обработанные в предыдущих запусках.
* **Проверка целостности фотографий.** После копирования SHA-256 исходника сравнивается с хешем копии.
* **Пакетная обработка.** Метаданные считываются партиями, размер которых можно настраивать.
* **Тестовый режим.** Параметр `-WhatIf` показывает планируемые операции без копирования файлов.
* **Журналирование.** Результаты обработки, дубликаты и ошибки сохраняются в CSV.

## Как работает сортировка

Архив организуется в следующую структуру:

```text
MediaArchive/
├── Photos/
│   ├── 2019/
│   │   ├── 06/
│   │   │   ├── IMG_001.jpg
│   │   │   └── IMG_002.jpg
│   │   └── 12/
│   └── 2020/
│       └── 01/
├── Videos/
│   ├── 2019/
│   │   └── 06/
│   └── 2020/
│       └── 01/
└── _media-collector-journal.csv
```

Фотографии и видео хранятся отдельно. Внутри каждого типа файлов создаются каталоги года и месяца.

### Определение даты фотографии

Скрипт последовательно проверяет доступные метаданные:

1. `DateTimeOriginal`
2. `SubSecDateTimeOriginal`
3. `CreateDate`
4. `DateCreated`
5. `MediaCreateDate`
6. `TrackCreateDate`
7. `ContentCreateDate`
8. `CreationDate`

Если подходящая дата отсутствует или не распознаётся, используется время последнего изменения файла (`LastWriteTime`).

### Определение даты видео

Для видео проверяются метаданные контейнера и временные метки создания:

* `MediaCreateDate`
* `CreateDate`
* `TrackCreateDate`
* `ContentCreateDate`
* `DateCreated`
* `CreationDate`
* `DateTimeOriginal`

Если подходящая дата отсутствует, используется `LastWriteTime`.

**Важно:** время последнего изменения файла не обязательно совпадает с датой съёмки. Например, после копирования или скачивания файла оно может быть изменено.

## Поиск дубликатов

Для фотографий используется алгоритм SHA-256.

1. Скрипт вычисляет хеши фотографий, уже находящихся в архиве.
2. Вычисляет SHA-256 исходной фотографии.
3. Проверяет, встречался ли такой хеш ранее.
4. Если фотография уже есть в архиве, повторная копия не создаётся.
5. После копирования вычисляется хеш целевого файла и сравнивается с исходным.

Таким образом, фотографии с разными именами, но одинаковым содержимым распознаются как дубликаты.

**Видео не хешируются и не проверяются на дубликаты.** Они копируются без вычисления SHA-256.

## Требования

* Windows с Windows PowerShell 5.1 или совместимой версией PowerShell.
* [ExifTool](https://exiftool.org/) — утилита для чтения метаданных изображений и видео.
* Доступ к исходным каталогам на чтение.
* Достаточно свободного места на диске назначения.
* Права на создание каталогов и файлов в архиве.

Скрипт не требует сторонних PowerShell-модулей.

## Установка

1. Скачайте `script.ps1` из репозитория.
2. Установите ExifTool для Windows.
3. Укажите путь к `exiftool.exe` через параметр `-ExifToolPath` либо разместите утилиту по пути, используемому по умолчанию.

По умолчанию скрипт ожидает ExifTool здесь:

```text
C:\script\exiftool\exiftool.exe
```

Если ExifTool находится в другом месте, передайте его фактический путь при запуске.

## Использование

### 1. Тестовый запуск

Рекомендуется всегда начинать с `-WhatIf`.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\script\script.ps1" -Source "D:\Photos" -Destination "E:\MediaArchive" -WhatIf
```

В тестовом режиме скрипт сканирует источники, анализирует метаданные, проверяет дубликаты фотографий и выводит планируемые пути назначения. Файлы не копируются, а журнал не используется для фиксации новых результатов тестового запуска.

Параметр `-ExecutionPolicy Bypass` действует только на запускаемый процесс PowerShell и не меняет системную политику выполнения сценариев.

### 2. Сбор из нескольких каталогов

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\script\script.ps1" -Source "D:\Photos" "D:\Camera" "E:\OldArchive" -Destination "E:\MediaArchive" -WhatIf
```

Пути передаются как отдельные значения параметра `-Source`. После проверки результата удалите `-WhatIf`, чтобы выполнить копирование.

### 3. Запуск с нестандартным путём к ExifTool

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\script\script.ps1" -Source "D:\Photos" -Destination "E:\MediaArchive" -ExifToolPath "C:\Tools\ExifTool\exiftool.exe" -WhatIf
```

### 4. Настройка размера пакета

По умолчанию скрипт обрабатывает до 200 файлов за один вызов ExifTool.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\script\script.ps1" -Source "D:\Photos" -Destination "E:\MediaArchive" -BatchSize 500 -WhatIf
```

Допустимый диапазон `-BatchSize`: от 1 до 2000.

Больший пакет может уменьшить накладные расходы на запуск ExifTool, но увеличивает объём данных, обрабатываемых за один вызов.

## Параметры

| Параметр        | Обязательный | По умолчанию                      | Описание                              |
| --------------- | ------------ | --------------------------------- | ------------------------------------- |
| `-Source`       | Да           | —                                 | Один или несколько исходных каталогов |
| `-Destination`  | Да           | —                                 | Корневой каталог медиаархива          |
| `-ExifToolPath` | Нет          | `C:\script\exiftool\exiftool.exe` | Путь к ExifTool                       |
| `-BatchSize`    | Нет          | `200`                             | Количество файлов в одной партии      |
| `-WhatIf`       | Нет          | Выключен                          | Тестовый режим без копирования        |

Исходные каталоги и каталог назначения не должны пересекаться. Скрипт отклоняет ситуации, когда архив находится внутри источника, источник находится внутри архива или они совпадают.

## Журнал

В корне архива создаётся файл:

```text
_media-collector-journal.csv
```

В журнал записываются:

* время операции;
* статус;
* тип медиа;
* путь к исходному файлу;
* путь к целевому файлу;
* SHA-256 фотографии;
* источник даты;
* описание ошибки, если она возникла.

Основные статусы:

| Статус           | Значение                           |
| ---------------- | ---------------------------------- |
| `CopiedPhoto`    | Фотография скопирована и проверена |
| `CopiedVideo`    | Видео скопировано                  |
| `DuplicatePhoto` | Фотография пропущена как дубликат  |
| `Error`          | При обработке возникла ошибка      |

При повторном запуске журнал используется для пропуска ранее обработанных файлов. Для записей о копировании проверяется существование целевого файла; для определения актуальности исходника используются путь, размер и время последнего изменения.

Поэтому журнал не является полноценной проверкой содержимого всех ранее обработанных файлов: если исходный файл изменился, его ключ изменится и файл будет обработан повторно.

## Безопасность данных

* Исходные фотографии и видео не перемещаются и не удаляются.
* Файлы копируются в архив.
* При совпадении имён существующие файлы не перезаписываются.
* Для фотографий после копирования проверяется совпадение SHA-256.
* При ошибках обработки информация по возможности записывается в журнал.
* Тестовый режим позволяет проверить план сортировки до копирования.

Перед обработкой единственной копии важного архива рекомендуется сделать резервную копию исходных данных.

## Поддерживаемые форматы

Список расширений включает распространённые форматы изображений и фотографий RAW, в том числе JPEG, PNG, HEIC, HEIF, WebP, AVIF, TIFF, BMP, GIF, DNG, CR2, CR3, NEF, ARW, ORF, RW2, RAF и PSD, а также распространённые форматы видео: MP4, MOV, M4V, AVI, MKV, WMV, MTS, M2TS, 3GP, MPEG, WebM, VOB, TS, FLV и другие.

Фактическая обработка зависит от корректности файла и доступности метаданных, а не только от расширения.

## Ограничения

* Дубликаты определяются только среди фотографий внутри каталога `Photos`.
* Видео не проверяются на дубликаты.
* Дата съёмки может быть недоступна или некорректна; в этом случае используется дата изменения файла.
* Имена файлов не сохраняют исходную структуру каталогов: архив организован по типу медиа, году и месяцу.
* Если в целевом каталоге уже существует файл с тем же именем, создаётся имя с числовым суффиксом.
* Скрипт не заменяет резервное копирование и не удаляет исходные данные.
* При прерывании во время копирования незавершённая операция может потребовать ручной проверки.
